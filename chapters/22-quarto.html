22  Documents & Presentations with Quarto

In the Integration module, you built analytical workflows that produce results inside Marimo notebooks. Notebooks are excellent for interactive exploration, but they aren’t always the right format for communicating your findings. A stakeholder who wants a written report shouldn’t have to open a notebook. A conference audience expects slides, not scrolling cells.

Quarto solves this problem. It’s a publishing system that renders Markdown into professional documents, presentations, websites, and more. You already know Markdown from README files and Git commit messages in Foundations. You already know how to produce data, charts, and tables with Polars and Altair from Integration. Quarto connects the two: you write Markdown with embedded code blocks, and Quarto renders it into a polished document where the code output, tables, and charts appear inline.

This book is written in Quarto. The course slides are written in Quarto. And your final exam presentation will be written in Quarto.

22.1 What Is Quarto?

Quarto is a command-line tool that takes a .qmd (Quarto Markdown) file and renders it into one of several output formats: HTML pages, PDF documents, Word files, or Revealjs slide decks. A .qmd file is just a Markdown file with a YAML header that specifies the output format and optional code blocks that Quarto executes during rendering.

The workflow is:

  1. Write a .qmd file in your editor (Zed).
  2. Include Markdown for narrative and code blocks for computations.
  3. Run uv run quarto render document.qmd from the terminal.
  4. Quarto executes the code, captures the output, and produces the finished document.

Install Quarto following the instructions at quarto.org. It’s a standalone tool (not a Python package), but it integrates with your uv-managed project by executing code in your project’s virtual environment.

22.2 Quarto Documents

22.2.1 The Anatomy of a .qmd File

Every Quarto document starts with a YAML front matter block that specifies metadata and the output format:

report.qmd
---
title: "Northwind Revenue Analysis"
author: "Your Name"
date: today
format: html
---

## Overview

This report analyzes revenue patterns across product categories
in the Northwind trading database.

## Revenue by Category

```{python}
import duckdb
import polars as pl

conn = duckdb.connect("data/northwind.duckdb", read_only=True)
revenue = conn.sql("""
    SELECT c.category_name, ROUND(SUM(od.unit_price * od.quantity), 2) AS revenue
    FROM order_details AS od
    JOIN products AS p ON od.product_id = p.product_id
    JOIN categories AS c ON p.category_id = c.category_id
    GROUP BY c.category_name
    ORDER BY revenue DESC
""").pl()

revenue
```

The Beverages category leads with the highest total revenue,
followed by Dairy Products and Confections.

When you run uv run quarto render report.qmd, Quarto executes the Python code block, captures the Polars DataFrame output as a formatted table, and embeds it in the rendered HTML document alongside your narrative.

22.2.2 YAML Front Matter

The YAML block controls the document’s metadata and output settings. Common options include:

front_matter.yaml
---
title: "Document Title"
author: "Your Name"
date: today                    # Automatically inserts today's date
format: html                   # Output format: html, pdf, docx, revealjs
toc: true                      # Add a table of contents
number-sections: true          # Number the section headings
code-fold: true                # Let readers expand/collapse code blocks
theme: cosmo                   # Visual theme for HTML output
---

The format field determines the output type. Changing format: html to format: docx renders the same content as a Word document. Changing it to format: revealjs renders it as a slide deck. The content stays the same; only the output changes.

22.2.3 Code Block Options

Code blocks in Quarto have execution options that control what appears in the rendered output:

code_options.qmd
```{python}
#| echo: true       # Show the source code in the output
#| eval: true       # Execute the code
#| output: true     # Show the code's output
#| warning: false   # Suppress warning messages
#| label: fig-revenue
#| fig-cap: "Revenue by product category"

import altair as alt

chart = alt.Chart(revenue).mark_bar().encode(
    x=alt.X("revenue:Q", title="Revenue ($)"),
    y=alt.Y("category_name:N", sort="-x", title=None),
)
chart
```

The #| lines are Quarto’s cell-level options. They’re written as YAML comments inside the code block. The most useful options:

For a report aimed at a technical audience, you might set echo: true so readers can see the code. For a report aimed at stakeholders, echo: false hides the code and shows only the output: tables, charts, and numbers.

22.2.4 Cross-References

Quarto supports cross-references to figures, tables, and sections. When you give a code block a label that starts with fig-, tbl-, or sec-, Quarto assigns it a number that you can reference elsewhere:

crossref.qmd
As shown in @fig-revenue, the Beverages category leads in total
revenue. See @tbl-summary for the complete breakdown.

```{python}
#| label: fig-revenue
#| fig-cap: "Revenue by product category"
chart
```

```{python}
#| label: tbl-summary
#| tbl-cap: "Category revenue summary"
revenue
```

In the rendered document, @fig-revenue becomes a clickable link like “Figure 1” and @tbl-summary becomes “Table 1.” This is the same cross-referencing system used throughout this book.

NoteExercise: Code Block Options Practice

You’re writing a Quarto report for stakeholders (non-technical audience). You have two code blocks:

  1. A SQL query that retrieves data (5 lines of code)
  2. An Altair bar chart that visualizes the results

What #| options would you set for each block to make the report readable for your audience, and why? Should you show the code, show warnings, include captions?

TipSolution

For the SQL query block:

#| echo: false      # Hide the code; they don't need to see SQL
#| eval: true       # Execute it to get the data
#| output: false    # Don't display raw output (data will feed to chart)

For the chart block:

#| echo: false                           # Hide the code
#| label: fig-revenue                    # Label for cross-reference
#| fig-cap: "Revenue by product category" # User-friendly caption

The principle: stakeholders want to see results (charts, tables, conclusions), not code. Non-technical audiences are distracted by implementation details. Use echo: false to hide code for presentation documents. Keep echo: true for technical documentation where the code itself is valuable.

22.2.5 Rendering to Different Formats

terminal
# Render to HTML (default for format: html)
uv run quarto render report.qmd

# Render to a specific format
uv run quarto render report.qmd --to html
uv run quarto render report.qmd --to docx
uv run quarto render report.qmd --to pdf

HTML output is self-contained (a single .html file with all assets embedded), making it easy to share by email or upload to a learning management system. PDF output requires a LaTeX installation, but the result is polished and printable. Word output produces .docx files that colleagues can edit, which is useful when collaboration requires document-level comments.

22.3 Embedding Visualizations and Tables

22.3.1 Altair Charts

Altair charts render as interactive HTML in Quarto documents. The chart specification is embedded in the output, so hovering and tooltips work just as they do in a Marimo notebook:

altair_embed.qmd
```{python}
#| echo: false
#| label: fig-trends
#| fig-cap: "Monthly revenue trends by category"

import altair as alt

line_chart = alt.Chart(monthly_revenue).mark_line().encode(
    x=alt.X("order_month:T", title="Month"),
    y=alt.Y("revenue:Q", title="Revenue ($)"),
    color="category_name:N",
).properties(width=600, height=350)

line_chart
```

Setting echo: false hides the code so the reader sees only the chart. This is the typical configuration for presentation documents.

22.3.2 Polars DataFrames as Tables

When a code block’s last expression is a Polars DataFrame, Quarto renders it as a formatted HTML table:

table_embed.qmd
```{python}
#| echo: false
#| label: tbl-categories
#| tbl-cap: "Revenue summary by product category"

revenue.head(5)
```

For more control over table formatting, Polars integrates with Quarto’s Great Tables support, but the default rendering is clean enough for most reports.

22.3.3 Multi-Panel Layouts

Quarto’s layout syntax lets you arrange multiple outputs side by side:

layout.qmd
::: {layout-ncol=2}

```{python}
#| echo: false
#| fig-cap: "Revenue by category"
bar_chart
```

```{python}
#| echo: false
#| fig-cap: "Monthly trends"
line_chart
```

:::

The layout-ncol=2 directive places the two charts in a two-column layout. This is useful for dashboard-style pages in a report where you want related charts next to each other.

22.4 Quarto Presentations (Revealjs)

Revealjs is a web-based presentation framework that produces HTML slide decks. Quarto renders .qmd files into Revealjs presentations with a single format change in the YAML header.

22.4.1 Slide Structure

In a Revealjs presentation, each level-2 heading (##) creates a new slide:

presentation.qmd
---
title: "Northwind Revenue Analysis"
author: "Your Name"
date: today
format: revealjs
---

## The Question

Which product categories drive Northwind's revenue,
and are there seasonal patterns in ordering behavior?

## Methodology

- Connected to the Northwind DuckDB database
- Analyzed 200,000+ orders across 8 product categories
- Computed monthly revenue and quarter-over-quarter growth

## Revenue by Category

```{python}
#| echo: false
bar_chart
```

## Monthly Trends

```{python}
#| echo: false
line_chart
```

## Key Findings

1. Beverages and Dairy Products account for 38% of total revenue
2. Order volume peaks in Q4, consistent with holiday demand
3. Seafood shows the highest quarter-over-quarter growth rate

## Recommendations

- Increase Beverages inventory ahead of Q4
- Investigate Seafood category growth drivers
- Monitor Confections for potential decline

Each ## heading becomes a slide title, and the content below it appears on that slide. Code blocks run during rendering, so charts and tables appear on the slides just as they would in an HTML document.

22.4.2 Incremental Lists and Speaker Notes

Revealjs supports incremental lists (items appear one at a time) and speaker notes (visible only to the presenter):

incremental.qmd
## Key Findings

::: {.incremental}
1. Beverages and Dairy Products account for 38% of total revenue
2. Order volume peaks in Q4, consistent with holiday demand
3. Seafood shows the highest quarter-over-quarter growth rate
:::

::: {.notes}
The seasonal pattern is consistent across all years in the dataset.
Q4 peaks are driven primarily by corporate gift orders.
:::

Speaker notes appear in the presenter view, which you access by pressing S while the presentation is open. The presenter view shows the current slide, speaker notes, a timer, and a preview of the next slide.

22.4.3 Rendering and Presenting

terminal
# Render the presentation
uv run quarto render presentation.qmd

# Or preview with live reload (re-renders on save)
uv run quarto preview presentation.qmd

The quarto preview command opens the presentation in your browser and automatically re-renders whenever you save the .qmd file. This tight feedback loop makes it easy to iterate on slide content and design.

22.5 Presenting Data Effectively

Building slides is a mechanical skill. Presenting data effectively is a communication skill. A few principles make the difference between slides that inform and slides that confuse.

Match the chart to the question. Bar charts compare quantities across categories. Line charts show trends over time. Scatter plots reveal relationships between two variables. Choose the chart that answers the specific question your slide poses.

Annotate the key finding. Don’t make your audience hunt for the insight. Use the slide title to state the finding (“Beverages drives 20% of revenue”) rather than describing the chart (“Revenue by Category”). Add emphasis to the relevant data point with color or a text annotation.

Simplify. Remove gridlines, legends, and axis elements that don’t serve the story. A chart on a slide should communicate one idea. If it requires explanation, it’s too complex.

Structure your narrative. A strong data presentation follows a pattern: Situation (what’s the context?), Question (what do we want to know?), Analysis (how did we investigate?), Finding (what did we discover?), Recommendation (what should we do?). This structure guides the audience through your reasoning and makes the conclusion feel earned.

Remember the difference between a notebook and a presentation. A notebook is for you: it documents your process, including dead ends and exploratory queries. A presentation is for your audience: it tells the polished story, skipping the dead ends and showing only the path to the insight.

NoteExercise: Render to Multiple Formats

You have a complete .qmd file with YAML header format: html. You want to render the same content as both an HTML report and a Revealjs presentation. What would you do?

Hint: there are at least two different approaches. Can you think of a way that doesn’t require duplicating the file?

TipSolution

Approach 1 (simplest): Keep the YAML as format: html, then use the command line to override:

uv run quarto render report.qmd                    # Renders as HTML
uv run quarto render report.qmd --to revealjs     # Renders as Revealjs

Approach 2 (if you want defaults): Use format: [html, revealjs] in the YAML to render to both formats with one command:

---
format: [html, revealjs]
---

This creates both an HTML file and a Revealjs presentation from the same source. The advantage is that your narrative and data are a single source of truth. Any updates to the analysis automatically appear in both output formats.

22.6 Exporting and Sharing

22.6.1 Self-Contained HTML

By default, Quarto renders HTML documents as self-contained files with all images, CSS, and JavaScript embedded. You can share the resulting .html file by email or upload it to a learning management system. The recipient opens it in any browser.

22.6.2 Marimo Notebook Export

Marimo notebooks can also be exported to HTML for sharing:

terminal
marimo export html notebook.py -o notebook.html

This produces a read-only HTML version of the notebook with all outputs rendered. It’s useful when the notebook is the deliverable and you want to share it with someone who doesn’t have Marimo installed.

22.6.3 The Deliverable Spectrum

Different audiences need different formats. Here’s how the tools you’ve learned map to communication contexts:

The analytical work is the same regardless of format. SQL retrieves the data, Polars transforms it, and Altair visualizes it. The only thing that changes is the presentation layer: a notebook, a document, slides, or an Excel file. Being able to target multiple formats from the same analysis is a professional advantage.

Summary

Quarto turns Markdown into professional documents and presentations. The .qmd format combines narrative, code, and output in a single file that renders to HTML, PDF, Word, or Revealjs slides. Code blocks execute during rendering, so Altair charts and Polars tables appear inline without manual screenshot or copy-paste.

Revealjs presentations use the same Markdown you already know, with level-2 headings creating new slides. Features like incremental lists, speaker notes, two-column layouts, and the presenter view make Quarto a practical tool for data presentations. The key communication principles, matching charts to questions, annotating key findings, simplifying visual elements, and structuring a narrative, apply regardless of the tool.

Your final exam presentation will be built in Quarto. The sooner you start drafting and iterating, the more polished the result will be.

Glossary

cross-reference
A link to a labeled figure, table, or section within a Quarto document. Written as @fig-label, @tbl-label, or @sec-label.
front matter
The YAML block at the top of a .qmd file that specifies metadata (title, author, date) and output settings (format, theme, table of contents).
Quarto
A publishing system that renders Markdown files (.qmd) into HTML, PDF, Word, and Revealjs presentations, with support for executable code blocks.
Revealjs
A web-based presentation framework. Quarto renders .qmd files into Revealjs HTML slide decks.
self-contained
An HTML file that embeds all assets (images, CSS, JavaScript) so it can be shared as a single file without external dependencies.
speaker notes
Presentation notes visible only to the presenter. Written in ::: {.notes} blocks and accessed via the presenter view (S key).
